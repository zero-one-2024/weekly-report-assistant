# Weekly Report Assistant

[English](README.md) | [简体中文](README.zh-CN.md)

一个 Codex 周报助手技能：将每周工作素材整理成中文周报，通过当前可用且已登录的浏览器，填写到**飞书「汇报」应用**并保存草稿。你复核后手动提交。

## 功能

- 汇总工作要点、明确引用的 Codex 聊天、本地记录及用户提供的文件，按项目归并，避免逐日流水账。
- 使用有依据的数量、版本、交付物及测试结果；缺少数据时保留待确认，不编造提升比例，不重复统计历史成果。
- 固定四个模块，逐项编号，**标题加粗、正文紧接标题且保持同段**，不同工作项之间空一行。
- 先保存本地草稿，再填写飞书；保留人工修改，保存后刷新，核对文字、格式与内容是否持久保存。
- 停在草稿阶段，不提交、不修改收件人，也不自行创建定时任务。

四个模块依次为：

1. 本周工作/项目推进重点进展&总结
2. 下周工作计划与安排
3. 需要协调与帮助
4. 其他需要同步的事项或说明

第一模块先写简短总述。助手推导的下周计划标注「建议，待确认」。后两个模块只有在你明确表示没有事项时才填写「无」，缺少信息时标记待确认。

## 使用条件

- Codex 能读取本地技能及你提供的素材。
- 可选的本地排版工具与测试需要 Python 3.9 及以上版本，并具有 `Asia/Shanghai` 时区数据；均只使用标准库，不需要安装第三方 Python 包。
- 填写飞书需要浏览器集成，能够读取和编辑已登录的汇报表单、设置富文本格式并刷新页面。单纯的搜索或网页抓取工具无法完成填写。本仓库不包含浏览器集成。

浏览器不可用或需要登录时，技能保留本地草稿，并说明剩余步骤，不会声称飞书已更新。「汇报」应用与飞书 Docx/Wiki 不同，本流程不使用 `lark-cli` 读取或填写周报。

## 安装

将仓库克隆到默认的 Codex 技能目录。若已安装同名技能，应更新现有安装，不覆盖已有目录。

```bash
mkdir -p ~/.codex/skills
git clone https://github.com/zero-one-2024/weekly-report-assistant.git ~/.codex/skills/weekly-report-assistant
```

私有仓库需要先完成 GitHub 身份认证。若配置了自定义 `CODEX_HOME`，使用其下的 `skills` 目录。安装后在新的 Codex 聊天中调用。

仓库所有者的本机安装可能通过符号链接指向开发工作区；保留现有安装，无需再次克隆。

## 调用示例

调用技能时提供统计周期、工作要点或素材引用，以及本周的飞书汇报链接：

```text
使用 $weekly-report-assistant，根据我提供的本周工作记录，整理
2026年11月2日至11月8日周报，填写到这个飞书汇报链接：<本周链接>。
保存并刷新核验草稿，不提交。
```

也可以只要求生成本地周报，或在保留已有修改的前提下补充某个事项。

日期统一按北京时间 `Asia/Shanghai` 处理。你明确指定的统计周期优先，否则默认本周一至周日；只把生成时点前实际完成的工作写为已完成。默认归档目录为 `/Users/dhl/WorkFile/13_工作周报`，不存在时使用当前工作目录；你也可以指定其他目录。写入前读取并遵循目标目录适用的规则。

## 编写格式

以下为**虚构排版示例**，不能当作实际工作成果：

**1. 项目文档编制：**完成2册独立手册，分别输出Word和PDF；监管方V1.0共10章、50页，项目方V1.0共8章、40页。

**2. 专项测试：**执行20项用例，通过15项、失败3项、阻塞2项，形成3项待修复问题。

飞书中必须呈现真正的加粗，不能把 Markdown 星号留在正文里。浏览器流程会在保存并刷新后检查实际格式。

## 本地排版工具

工具将助手准备的 JSON 草稿转换为 Markdown 和四栏富文本载荷。使用技能不要求你手工填写 JSON；输入结构及虚构示例见[草稿数据与排版工具](references/draft-format.md)。

在仓库根目录执行：

```bash
python3 scripts/render_report.py /绝对路径/本周事实.json --output /绝对路径/周报/2026-11-02_2026-11-08_工作周报.md
```

输出指定的 `.md` 文件及同名 `.fields.json`。载荷为每栏提供纯文本、Markdown、HTML 和按 UTF-16 计算的标题选区；来源说明与内部核对内容不进入四栏载荷。

默认拒绝覆盖已有输出。先将最新人工修改合并到输入，再使用 `--replace`，工具会先把两份旧输出备份至 `历史版本/`，然后替换本地文件。此选项不授权覆盖远端周报。

工具只检查结构与来源引用是否存在，不判断来源能否支持某项结论或数字是否真实，也不连接飞书。初始输出始终标记为尚未填写、尚未核验的本地草稿；实际浏览器核验结果另行记录。

## 测试与验证

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
```

测试覆盖四栏输出、同段加粗、段间空行、HTML 转义、UTF-16 选区、来源引用、北京时间转换、完整链接保留、覆盖保护、备份及命令行行为，也会实际执行文档中的 JSON 示例。

这些是本地测试。浏览器访问、飞书编辑器行为及草稿持久保存，仍需在实际填写时验证；测试不会访问或提交真实周报。
