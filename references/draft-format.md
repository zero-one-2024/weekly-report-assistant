# 草稿数据与排版工具

`scripts/render_report.py` 只使用 Python 3.9+ 标准库，不访问网络或操控飞书。将核对过的材料写成 UTF-8 JSON，再生成本地 Markdown 和浏览器可用的四栏载荷。JSON 是助手的内部工作格式，不要求用户填写。

```json
{
  "period_start": "2026-11-02",
  "period_end": "2026-11-08",
  "generated_at": "2026-11-08T19:00:00+08:00",
  "feishu_url": null,
  "summary": "本周完成项目文档编制，并开展专项测试。",
  "sources": {
    "s1": "用户指定的本周记录：演示数据，仅用于排版测试"
  },
  "sections": {
    "progress": [
      {
        "title": "项目文档编制",
        "body": "完成2册手册，分别输出Word及PDF。",
        "source_ids": ["s1"]
      }
    ],
    "plans": [
      {
        "title": "补齐操作配图",
        "body": "结合遗留事项补充配图，具体范围待确认。",
        "source_ids": ["s1"],
        "suggested": true
      }
    ],
    "coordination": "待确认",
    "other": "无"
  },
  "pending": ["确认是否有协调需求"]
}
```

示例为虚构数据，不是用户业绩。必填字段为起止日期、`sources` 和四栏 `sections`。`generated_at` 可省略，自动取当前北京时间；提供时必须有时区。指定日期范围可以不是完整自然周。

- 第一栏 `progress` 必须有至少一条有来源的工作；整周无材料时不生成虚构内容。第一栏总述 `summary` 建议填写。
- 其他三栏为工作项数组，或「无」「待确认」等明确的一段纯文本。没有计划资料时可先标记「待确认」，不能擅自生成已承诺的计划。
- 每个工作项须有 `title`、`body`、非空的 `source_ids`；来源 ID 必须存在于 `sources`。建议计划也引用推导所依据的材料。`suggested` 只用于 `plans`，为 `true` 时标题自动添加「建议，待确认」。工具只检查来源引用存在，不证明该来源支持正文。
- 标题、正文与单段文本均为纯文本，不写 Markdown / HTML 标记；不包含人为换行。Markdown 和 HTML 特殊字符由工具转义，展示时原样保留。
- `feishu_url` 为本次完整链接或 `null`，参数原样保留。缺链接时本地标记待补。不要填历史示例链接。
- `pending` 为正文之外的待确认事项列表。素材覆盖日期及更详细的事实核对结果，可在生成后补入 Markdown 内部核对区；重新生成前保存这些人工修改。

在本技能目录执行，替换为本次真实文件路径：

```bash
python3 scripts/render_report.py /绝对路径/本周事实.json --output /绝对路径/周报/2026-11-02_2026-11-08_工作周报.md
```

输出两个文件：

- 指定的 `.md`：元信息、四栏正文、来源索引与待确认事项。初始状态始终是「本地草稿，未填写飞书，未提交」。
- 同名 `.fields.json`：四栏独立的纯文本、Markdown、HTML 片段和标题选区；不含来源和内部核对内容。标题选区偏移以 UTF-16 代码单元计算。

默认拒绝覆盖任一已有输出，避免丢失用户修改。确需重新生成时，先合并最新修改，再添加 `--replace`；旧输出自动保存到同目录 `历史版本/` 下带时间戳的目录。该选项只表示允许替换本地文件，不授权远端覆盖。保留输入事实 JSON，后续修订以核对过的最新版本为准。

工具不能判断数字真伪、来源支持程度、内容是否完整或页面是否保存。使用它不能省略事实检查和浏览器刷新核验。
