# 浏览器填写与核验

在确实要填写飞书汇报时读取。本文件描述可观察结果，不绑定某个已过期的浏览器工具。

## 连接与目标确认

1. 从当前工具列表发现已登录浏览器的读取、编辑、富文本输入与刷新能力；如工具要求专用浏览器技能，先加载该技能并遵守接口。`node_repl` 只有在当前环境明确提供浏览器运行时接入方法时才可用于控制页面，不能猜测旧会话的 `cua` / `browser` 对象或连接端口。普通网页搜索、抓取及 `open_in_codex` 打开页面本身不能证明具备编辑能力。
2. 使用用户本次提供的完整原始 URL 定位或打开页面。历史链接只作为历史资料，不自动复用。需登录时让用户在浏览器完成登录，不收集密码、验证码或 cookie。
3. 读取页面，核对当前账户、周报模板、实际统计周期、四栏标签以及是否已提交。链接的 `ruleId` 可能固定，不能仅凭 URL 认定周次。周次不明或与本次不符时，暂停写入并向用户确认；已提交的历史记录不改写。
4. 读取四栏当前正文与格式，保存改稿前快照到本周归档目录的历史版本。若页面已有人工修改，与本地素材合并；冲突只询问无法判断的部分，不整栏重置。

## 富文本输入

`render_report.py` 生成的 `.fields.json` 包含每栏 `text`、`markdown`、`html` 及 `title_spans`，仅 `fields` 下的四栏内容用于页面输入。内部核对区和元数据不粘贴到四栏中。

- 按可见标签定位编辑器，建立标签到控件的实际映射。先实际核对 DOM / 可访问性结构，再使用选择器，不直接假定第 N 个 `contenteditable` 就是某栏。
- 优先采用浏览器工具支持的富文本粘贴，将 HTML 与纯文本一起输入；HTML 每项为同一个 `<p>` 中的 `<strong>编号. 标题：</strong>正文`，工作项之间有空段落。
- 若只有纯文本输入，先填 `text`，再通过编辑器实际工具栏或选区格式命令将编号与标题加粗。`title_spans` 使用 JavaScript / 浏览器一致的 UTF-16 偏移；必须确认编辑器文本与载荷一致后才可用于选择，不能把偏移盲目套在已被编辑器改写的 DOM 中。
- 不把带 `**` 的 Markdown 当作最终富文本；除非实际核验编辑器已转换，否则星号会成为正文。不能将标题与正文分别粘为两个段落。
- 使用受支持的编辑器输入触发正常保存。不直接改 DOM 的 `innerHTML`、不注入未观察到的内部 API，不把截图看起来正确当作保存成功。
- 无法设置粗体或保持同段时，保留已完成的草稿与格式缺口，不能声称格式核验通过。

## 保存与刷新核验

1. 写入后读取四栏文本、实际段落和粗体范围，检查标题与正文同段、正文未被整段加粗、各事项间空一行、没有 Markdown 星号残留。
2. 等待页面实际显示已保存；如有明确的「保存草稿」按钮可使用。不要点击任何提交、发送或发布按钮，不用可能触发提交的整表快捷键。
3. 保存完成后刷新页面，重新定位和回读四栏，确认周期和草稿状态，逐栏比对预期内容，并再次检查粗体与段落。可统一处理 CRLF/LF 和编辑器产生的 NBSP、零宽占位符，但不任意删除标点、数字或段落来制造匹配。
4. 「提交」按钮仍存在本身不足以证明保存或未提交；结合草稿状态、已保存提示及刷新后内容综合核验。连接中断时先回读当前页面，未确认保存前不刷新以免丢失输入。
5. 有必要时保存本次截图作为辅助证据；截图不能替代逐栏文字、格式和持久化核验。
6. 在本地内部核对区记录实际核验时间、目标周期、保存状态、逐栏文字与格式结果。未验证的项目明确列为未验证，不改写为成功。

仅当填写及刷新核验均成功，才交付「已保存草稿，未提交」。不操作提交，无需请求提交权限；由用户在复核后手动提交。
